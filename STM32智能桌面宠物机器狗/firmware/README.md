# 固件结构说明

> 平台：STM32F103C8T6，Keil MDK（标准外设库）+ CH340 串口 ISP
> 代码规模：约 2k 行 C，单工程
> 说明：本文件描述固件结构与关键实现，源码未随仓库公开。

---

## 一、文件划分

```
Core/
├── main.c              主循环、初始化、状态机调度
├── servo.c/.h          五路 PWM 初始化、角度→脉宽换算、限幅
├── action.c/.h         动作帧表 + 帧调度器
├── protocol.c/.h       串口帧解析（CRC/累加和校验）、指令分发
├── oled.c/.h           OLED 驱动（软件 I2C）+ 表情绘制
├── voice.c/.h          语音串口收发
├── bt.c/.h             蓝牙串口收发
└── board.c/.h          GPIO、时钟、ADC（电量）初始化
```

分层的目的只有一个：**加动作不改代码，只改表**。

---

## 二、三层结构

```
指令层  protocol.c    收到帧 → 校验 → 查表得 CMD → 投递指令
   ↓
动作层  action.c      CMD → 选动作帧表 → 按 20ms 节拍推进 → 输出五路角度
   ↓
执行层  servo.c       角度 → 比较值 → TIM 寄存器
```

### 指令层

- 串口中断里只做"收字节进环形缓冲"，解析放主循环，避免中断里跑重活
- 同一套解析函数给 USART1 和 USART3 复用，靠传入的"来源"参数区分，日志里能看出是谁发的指令

### 动作层

- 每个动作 = 一张关键帧表（`const Frame_t[]`），字段：五路角度 + 保持时长
- 调度器记录"当前第几帧、这一帧还剩多少 tick"，每 20ms 走一格
- 帧之间是直接跳到目标角度（未做缓动），这是当前动作偏硬的原因

### 执行层

- TIM2 四通道 + TIM3 一通道，50Hz
- 角度换算：`CCR = 500 + angle * 1000 / 180`（按 72MHz / 预分频算出来的值，单位 µs 对齐 0.5~2.5ms）
- 写寄存器前统一限幅到 20°~160°，防止顶结构死点

## 三、状态机

```
        ┌──────┐  收到动作指令   ┌────────┐
        │ IDLE │ ──────────────▶ │ ACTION │
        └──────┘                 └────────┘
           ▲                          │ 帧表走完
           │       ┌──────┐           │
           └───────│SLEEP │◀──────────┘（收到 0x09）
                   └──────┘
                      │ 任意指令唤醒
                      ▼
                    IDLE
```

- `ACTION` 期间收到新动作：先回 0x01 立正，再执行新的（防止姿态错乱）
- `摇尾巴` 不占状态机，作为可叠加动作单独跑
- `SLEEP` 期间呼吸灯周期放慢、OLED 切睡眠表情、舵机 30s 后松力

## 四、几个实现细节

### 不用 delay

所有动作计时走 TIM 中断节拍 + 计数变量，主循环里没有一处 `delay_ms()`。早期版本用了 delay，结果动作执行期间串口不响应，发"停止"没反应。

### 舵机松力

静止 30s 后把对应通道的比较值置 0（不再输出脉冲），舵机不再抖，也省电。代价是姿态会松一点点，所以"趴下"这种需要保持的姿态不松力。

### 调试指令 0x20

`0x20 + 通道 + 角度` 直接写单路，绕过动作层。调结构、找中立位的时候用串口助手一点一点试，比改代码烧录快两个数量级。

### 电量采样

ADC 连续采样 16 次，去掉最大最小各 2 个再平均，按分压比反算电池电压。低于阈值时 OLED 角上闪一个电池图标——后来发现玩到一半断电太难受，才加的。
